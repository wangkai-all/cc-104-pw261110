# 调查表整理工具

把一批结构相似的 Word 调查表（`.docx`）整理成一张统一、可追溯的数据表。

- 页面左侧显示原始表格，右侧选择字段对应关系，预览确认后再导入。
- 每个导入值都带来源：文件（含 SHA-256）、表格、原始行列号；继承来的地区名称还会标出继承自哪一行。
- 空白单元格、填写“无”、填写数字 0 分别保存为 `blank` / `none` / `zero` 三种状态，导出与计数都不合并。
- 表格附注、脚注（`①②③` 等标记）、小计/合计行不会混入数值。
- 地区名称只在同一数据段内向下继承；小计行、重复表头、附注行、空行或另一张表格都会中断继承。
- 嵌套表、无法确定的数据区会列为“待确认项”，由页面选定范围、跳过或单独导入后继续。
- 映射方案可保存并复用到结构相同的文件；结构变化时逐项列出差异并拒绝套用，避免按列错位导入。
- 相同文件重复上传只登记一次；相同文件 + 相同映射重复导入不会生成第二批数据。
- 更正映射后先预览差异，确认导入时生成新批次，旧批次标记为“已替换”但数据与原文件都保留。

## 运行

需要 Node.js ≥ 22.5（使用内置 `node:sqlite`，无需额外数据库）。

```bash
npm install
npm start          # http://localhost:5173
```

自定义数据目录或端口：

```bash
DATA_DIR=/path/to/data PORT=5173 npm start
```

数据保存在 `data/`（SQLite 数据库 `data/db/app.sqlite` 加上 `data/uploads/` 中的原始 DOCX 文件），已被 `.gitignore` 忽略。上传的原文件会一直保留，可在批次列表中重新下载。

运行测试（不需要数据库服务、不依赖 Python）：

```bash
npm test
```

## 演示流程（全部示例文件均不含个人信息）

示例文件位于 `samples/`，也可在页面“载入示例文件”里直接打开：

| 文件 | 用途 |
| --- | --- |
| `sample_survey.docx` | 主样本：两行合并表头、纵向合并地区、重复表头、小计行、表内附注、嵌套表；空白/“无”/0 齐全 |
| `sample_survey_second.docx` | 与主样本结构相同、数据不同，用于验证方案复用 |
| `sample_survey_revised.docx` | 结构性修订：少一列、表头改名、表头由两行变一行，用于验证差异拦截 |
| `sample_nested.docx` | 单元格内嵌表格的样本，用于验证“待确认项” |

完整流程：

1. **上传**：点“载入示例文件”选 `sample_survey.docx`。再次上传同一文件会提示“此前已上传”，不生成新文件或新批次。
2. **字段对应**：左侧原表按行类型着色（标题/表头/数据/小计/附注/重复表头/范围外）。右侧确认表头行、数据区起止、地区列、字段的来源列与类型。
3. **待确认项**：切到“数据区 2”，嵌套表会作为阻止导入的待确认项出现，点“跳过该嵌套表”后继续。
4. **预览**：7 行、53 个取值，空白 5 / “无” 2 / 零 2。点击任一取值可定位原单元格，并显示文件、表格、行列、原始文字；继承的地区名称显示“← 继承 R4”。
5. **保存方案**：填写方案名称后“保存映射方案”，再到“方案库”把方案应用到 `sample_survey_second.docx` —— 结构核对通过并直接套用。
6. **差异拦截**：把同一方案应用到 `sample_survey_revised.docx`，页面列出具体差异（列数 9→8、缺少第 4 列「检测频次」、第 6 列「水质」→「水质评价」等）并拒绝套用，不会生成批次。
7. **更正映射**：回到“字段对应”修改后生成新预览，页面显示与上一批次的差异；确认导入后新批次为“已导入”，旧批次变为“已替换”且仍可查看数据、导出 CSV、下载原文件。

## 接口概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/files` | 上传 DOCX（原始字节作为请求体，`x-file-name` 指定文件名）；按 SHA-256 去重 |
| POST | `/api/files/:id/suggest` | 自动生成映射方案；带 `tableOrdinal` 时只分析该表 |
| POST | `/api/files/:id/analyze` | 用指定的表头/范围/地区列重新分析单个数据区 |
| GET/POST/DELETE | `/api/specs` | 映射方案库 |
| POST | `/api/specs/:id/apply` | 套用方案到文件；结构不一致返回 409 与具体差异 |
| POST | `/api/preview` | 生成预览，并与上一已导入批次比较差异 |
| POST | `/api/batches` | 生成预览批次或确认导入（`commit: true`）；重复映射返回 `duplicate` |
| GET | `/api/batches/:id` | 批次详情（记录与每个取值的来源信息） |
| GET | `/api/batches/:id/csv` | 导出 UTF-8 CSV |
| GET | `/api/batches/:id/diff?against=` | 两个批次之间的差异 |
| GET | `/api/values/:id` | 单个取值的完整来源链 |
| GET | `/api/files/:id/original` | 下载原始 DOCX |

## 目录

```
server/
  index.js      Express 应用与路由
  docx.js       DOCX（OOXML）解析：网格、合并、嵌套表、附注、脚注
  xml.js        轻量 XML 解析器
  zip.js        ZIP 读取（中央目录）
  structure.js  表头识别、数据区分段、地区继承、待确认项
  engine.js     方案建议、结构比对、取值提取与来源记录
  store.js      SQLite 持久化
public/         前端页面（原生 ES 模块，无构建步骤）
samples/        不含个人信息的示例 DOCX
tests/          node:test 测试（含无依赖 DOCX 构造器）
tools/          示例文件生成脚本
```

## 已知边界

- 只支持 `.docx`；`.doc` 需先在 Word 中另存为 `.docx`。
- 数据区范围依靠表头、行类型启发式识别；无法确定时一定列为待确认项，不会静默猜测。
- 方案里的字段按表头文字与列位置核对；表头改名会作为差异报告，不会自动重映射。
